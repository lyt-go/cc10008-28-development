# 行为特征分析与事件溯源平台

面向用户行为打点采集、事件参数规范、会话重放、热力图分析、特征工程提取与行为标签体系管理的本地化数据分析应用平台。

这是一个**纯前端**管理平台：Vue 3 + Vite + TypeScript，仓库里没有后端服务。业务数据由
`frontend/src/data/` 下的本地数据层提供：首次打开用示例数据播种，之后的登记、筛选与状态流转
结果都持久化在浏览器 `localStorage` 里，刷新或重开浏览器都还在。dev server 已关掉自动打开页面，
启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端（唯一运行单元）
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/local-service.ts   本地数据服务：列表、筛选、动作流转、导出
│   ├── src/data/             模块元数据 / 示例数据 / localStorage 持久化
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false，无 /api 代理）
├── .gitignore
└── docker-compose.yml
```

## 启动

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，需要自己访问。

生产构建：

```bash
cd frontend
npm run build
```

## 约定

- 每个模块的页面在 `frontend/src/views/<模块>/index.vue`，页面只负责渲染，读写统一走
  `frontend/src/api/local-service.ts`。
- 字段、状态、动作与流转目标集中在 `frontend/src/data/modules.ts`；示例数据在
  `frontend/src/data/seed.ts`。
- 状态流转只允许在 `local-service.ts` 里改，页面组件不做业务判断。
- 想回到初始数据：清掉浏览器里 `behavior-event-trace-hub:entries` 这一项，或调用 `resetModule(模块)`。

## 统一发布窗口

`/release` 是事件规范、特征工程、行动标签共同读取的发布入口：三个模块在一个窗口里发布一份跨模块兼容
发布清单，只保留一份当前冻结版本。发布态单独持久化在 `behavior-event-trace-hub:release`，页面只读当前
冻结版本，历史对照窗口不再被业务页面读取。

- **兼容发布清单**：事件定义 / 特征模板 / 标签规则三个对象 + 修订号 + 摘要，同一窗口内只允许一份完整版本落库。
- **联合核验**：清单由事件侧和特征/标签侧两个业务面共同核对，每侧只写自己看得见的对象，单侧拿不到完整结论。
- **冲突回执**：同窗口并发提交时后到请求整体被拦，回执保留三个对象各自的失败位置；被拦请求重提只生成一份
  新清单，之后同内容的回执统一记为「跨模块发布窗口冲突」。
- **复核数据清单**：每次落库新清单都由特征工程生成一份，数据流是「事件定义 → 兼容发布清单 → 特征模板 / 标签规则」，
  在特征工程页面下方展示。
- **迟到修订仲裁**：`最晚完整窗口` 生成含迟到修订的新完整窗口，并把旧窗口降为历史对照；`首个确认窗口` 保持首发
  冻结清单不变，迟到修订进入待审队列。两种做法下每个窗口始终只有一份当前冻结版本。
- 首次打开会播种演示窗口 `WIN-EVEN-0003`（EVEN-0003 / FEAT-0003 / ACTI-0003），三个业务页面读到的是同一
  份 `MFST-0001` 冻结清单；「重置发布状态」可恢复到该演示窗口。
